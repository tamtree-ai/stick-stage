# Decisions

Decisions not covered by the plan. Newest last.

## 2026-09-26 (M0/M1)
- **Repo root is `repo/`** inside the project folder, next to `planning/`, `reports/` and `research_notes/`.
- **Pinned versions:** Remotion 4.0.529 (all `@remotion/*` exact). `zod` is pinned to 4.5.4 because Remotion's version check requires exactly that. TypeScript is 5.7.3 and ESLint 9 because `@remotion/eslint-config-flat` bundles typescript-eslint 8.21 (peer range `<5.8`, `eslint ^9`).
- **Contact sheet:** Remotion's bundled ffmpeg has no `tile` filter. `scripts/sheet.ts` renders frames with `renderFrames`, then tiles them in a `ContactSheet` still composition (frames are passed as data URLs). This needs no system ffmpeg and gives frame-number labels.
- **Pose transitions:** a custom `easeOutBack` (overshoot 1.2) over 4 frames instead of Remotion `spring()`, so the move length is exact and testable. Anticipation adds a 2-frame, 12% opposite dip, only for poses flagged `anticipation: true` (`arms-up`, `recoil`).
- **Expression transitions:** numeric channels (lids, brows, gaze, mouth params) blend over 3 frames with ease-out. Eye shape and symbols snap on the key frame.
- **Mouths are parametric** (`w, open, curve, skew, round, top, teeth, tongue`). Presets and, in M2, Rhubarb visemes are points in one space, so they blend instead of swapping SVGs.
- **Limbs:** a quadratic Bézier with the control point 0.55× past the joint (it passes near the elbow and rounds sharp bends instead of looping), plus a constant bow of `limbCurve × span × 0.14`. Legs use 0.6× the character's curve.
- **Legs are world-relative** (not torso-relative), so torso lean never tips the stance. Arms are torso-relative.
- **Case-insensitive filesystem:** the pure state module is `rig/actorState.ts` so it can't collide with `rig/Actor.tsx`.

## 2026-09-26 (face close-ups)
- **Face framings are tighter than the plan's first guess.** Because the characters are big-headed, a `close` with the head at 45% of frame width showed almost the whole body in 9:16. Tuned values (head width / eye line): `medium` 0.40 / 0.30, `close` 0.62 / 0.36, `extreme` 0.84 / 0.42. `extreme` stops at 0.84 so the head outline and hair stay inside the frame.
- **Face shots center the head, not the eyes.** The eyes sit forward on the head, so centering on them clipped the back of the head and June's bun. There is 3% lead room in the facing direction.
- **Closeups are a real camera zoom.** Line weight scales with the shot; there is no stroke compensation. The close-up sheets are the check on whether the 12 px strokes still look right at 3–4× zoom.
- **Emotion → framing lives in the expression data** (`closeup` hint), so the director (M4) and the skill (M5) read one source.

## 2026-09-26 (M2 talking)
- **M1 taste gate passed** (team approval, 2026-09-26). The M1 tuned numbers above are final for now.
- **TTS comes from the tamtree agent harness, not this repo.** The plan's `TtsAdapter` + provider became an input contract: the harness writes `voice/<line>.wav` + `voice.json` (`docs/voice-contract.md`). Provider choice, keys, cost tracking and TTS caching live in the harness. `pnpm voice:say` (macOS `say`) is the local stand-in and writes the same contract.
- **`pnpm prep`, not `pnpm prepare`.** npm/pnpm run a script named `prepare` on every install.
- **Prep cache key** = sha256(audio bytes, line fields, mouth tool + version, `PREP_VERSION`). One JSON per line in `generated/cache/`. Bump `PREP_VERSION` when prep output changes for the same inputs.
- **Rhubarb 1.14.0** is run with `--extendedShapes GHX` and the line text as the dialog file. The macOS release is x86_64 and runs under Rosetta on Apple Silicon. Audio is normalized to mono 16-bit 22.05 kHz WAV with Remotion's bundled ffmpeg (no system ffmpeg). That ffmpeg can't read AIFF, so `voice:say` asks `say` for WAV directly.
- **Visemes are points in the parametric mouth space** (`face/visemes.ts`). While talking, the viseme supplies opening/shape and the expression keeps 70% of its corner lift and smirk, so a happy line is smiling speech and an angry one is a frowning shout. Rest (X) and silence show the expression mouth itself. Shapes blend over 45 ms.
- **Estimated word timings use the audio.** When the voice source gives no word timings, prep detects pauses (10 ms RMS windows, −32 dB of peak, pauses ≥ 140 ms), matches them to punctuation breaks with a small least-squares DP, and spreads each phrase by syllables over its spoken span. Rhubarb's own rest cues were too sparse to find pauses.
- **Word anchors prefer the exact token.** "Forty!" matches the second token `Forty!` before the normalized match `forty` (the first "Forty"). The skit schema in M4 still adds `occurrence`.
- **Subtitles:** Montserrat variable font (OFL) vendored in `public/fonts/`, loaded with `@remotion/fonts`. 74 px, weight 800, white with a black outline and drop shadow. The spoken word turns yellow and lifts 0.1 em at 1.05× (the second cue besides color). Pages hold ≤ 26 chars and ≤ 1.2 s of speech, never span two lines, and linger 350 ms after the last word. The block is centered at 62% of frame height.
- **Slam text** sits at 64% height (below the face in every framing) and subtitles hide while a slam is up, since the slam is the word.
- **Safe area** starts as one profile in `src/data/safe-area.json`: top 14%, bottom 30%, left 4%, right 12%.
- **TalkLab shots are locked off:** the camera is framed from the actor at the line's first frame, not per frame, so gestures don't drag the camera.

## 2026-09-26 (M3 staging)
- **M2 gate passed** (team approval of `TalkLabClean.mp4`, 2026-09-26). `m2-talking` merged into `main`.
- **Set parts are registered in one table** (`set/parts/registry.ts`, `PART_INFO`) with their kits, whether they fill the frame (`backdrop`) and whether they belong in `foreground`. SetLab and the data tests read it. `KIT_BACKDROP` is the minimal backdrop per kit.
- **25 set parts across 5 kits.** Interior: wall, floor, window (`variant: "blinds"` for offices), shelf, frame, plant, door, couch, clock. Office: whiteboard, cabinet, chair, desk (foreground; variants `monitor`/`laptop`/`clear`). Park: sky (`variant: "sun"`), hills, grass (`variant: "path"`), tree, bush, bench, lamp. Street: buildings, sidewalk (+ curb and road), shopfront (seeded sign icon), hydrant. All colors come from the 7 palette tokens or `derived(palette)` (wood, metal, glass, paper, foliage), which mixes tokens, so there is still no raw hex in any part.
- **Palettes:** added `meadow`, `autumn` (outdoor, green/olive grass) and `city`, `dusk` (streets). A park in `dusk` gave purple grass, so each kit is reviewed in its own 3 palettes (`LAB_PALETTES` in `SetLab.tsx`).
- **Outdoor depth without perspective:** the park ground starts at a horizon `0.34 × figure` above `groundY`, and street facades meet the sidewalk `0.18 × figure` above it. Characters stand on the near ground, and no parts are scaled for depth.
- **Parts can snap to marks** (`mark` + `dx`) instead of `x`, so a desk and chair follow the cast mark. `seatFor: [marks]` says which cast member sits on a seat part.
- **Seating is an actor track, not a pose.** `seatKeys: [{ frame, seatPx | null }]` sits or stands, and the upper body still comes from whatever pose is active, so a seated character can point or facepalm. The `sit` pose is the rest pose for sitting (hands forward on the lap/desk). Seat heights (× figure height): chair 0.19, bench 0.18, couch 0.17. The director resolves them with `seatHeightAt(set, mark)`.
- **Seated legs use a 2-bone IK** (`rig/seat.ts`). The body's underside (hip + half the stroke, or the bottom of the bean torso) rests on the seat top, and each foot is planted on the floor in front (the back foot at 0.82× the front reach). If the seat is too high, the feet dangle. The legs blend FK → IK over 6 frames when sitting (ease-out) and back over 5 when standing up. The hip never drops below the height that keeps the feet on the floor, so feet never sink mid-transition. A "plop" overshoot was tried and dropped: with planted feet there's nothing to overshoot without pushing the feet through the floor.
- **Props are JSON** (`src/data/props/*.json`: kind, colors, size, `align`, `angle`, sign `text`). The geometry per kind lives in `props/draw.tsx`. Props are drawn in the character layer with the character's stroke (0.75× width), between the arm and the hand nub so the nub reads as the grip. `align: "forearm"` (phone, mic) follows the elbow→hand direction; `"upright"` (cup, laptop, sign) stays vertical. Sign text counter-flips on left-facing characters.
- **Prop track:** `propKeys: [{ frame, hand, prop | null, drop? }]`. A pickup pops in over 4 frames. `drop: true` releases the previously held prop from the hand's position at that frame (re-evaluated, so it stays frame-pure): a small up-and-forward arc, gravity 7 × figure/s², one spin, then it lands lying on its side with one small bounce. It stays on the floor until the same prop is picked up again. Dropped props live in figure space, so **when M4 adds `slideTo` they must move to stage space.**
- **Symbol FX:** `exclaim` (!), `question` (?, wobbles and counter-flips when mirrored) and `speed-lines` (radial shock lines that flicker every 2 frames) join sweat, anger, blush and tears. `!` and `?` have a white halo so they read over any set. `symbolKeys: [{ frame, symbol, durationFrames = 30 }]` pops a symbol on top of the expression, with its own entry pop, for the M4 `symbol` action. `?` is hidden while `!` shows (they share a spot).
- **New poses:** `sit`, `hold-out` (mic / offering), `hold-chest` (cup, laptop), `hold-up` (sign; the hand is far enough forward that the stick clears the face). They are `EXTRA_POSE_IDS`, so M1 labs that cycle `POSE_IDS` are unchanged.

## 2026-09-26 (M4 director)
- **M3 gate passed** (team review of `SetLab.png` + `StagingLabClean.mp4`, 2026-09-26). `m3-staging` merged into `main`.
- **Desk height stays at 0.34 × figure height** (team decision), so a seated character's shoulders and pointing gestures clear the desk.
- **Outdoor palettes stay as reviewed:** park uses `meadow` / `autumn` / `mint`, street uses `city` / `dusk` / `peach`. The defaults are `meadow` (park) and `city` (street).
- **Skits compile in the engine, in one pure function** (`compileSkit`: skit JSON + prepared voice + library → `Timeline`). The Studio (`calculateMetadata`), `pnpm compile` and `pnpm render` all call it, so the Studio, the CLI and the M5 skill see the same diagnostics. The timeline is plain JSON: cameras are solved at compile time (cuts are locked off at the cut frame) and written to `generated/timeline.json`.
- **Errors are diagnostics, not exceptions from deep inside.** Shape errors come from zod and library errors from a second pass (unknown pose/expression/prop/sound/cast id, with a did-you-mean). Both carry path + expected + example, and all of them are reported at once.
- **Beat timing:** lead-in 300 ms, a default gap of 250 ms between beats, tail 700 ms, silent beats 900 ms. A beat's `pauseBeforeMs` is dead air that **holds on the previous shot**; the beat (and any cut) starts when its line starts. `ms` anchors are relative to the line start and may be negative to reach into the pause.
- **Punchline reaction beat:** after the punchline (flagged, else the last spoken beat) the director inserts a silent 1.3 s reaction beat for the listener (whoever last spoke to the speaker). It's skipped if the next beat is already silent or `reaction: false`. The reaction expression comes from `beat.reaction`, else `reactions.json` → `punchline[speaker expression]`.
- **Listener auto-reactions:** gaze toward the speaker (x only, so the expression keeps its y), a nod on ~60% (seeded) of lines ≥ 1.4 s, and `reactions.json` → `listen[speaker expression]` on the last word. Each one is skipped when the skit gives that listener the same kind of action in the beat. On the punchline the listener holds, and the reaction goes to the reaction beat.
- **Shot policy details** beyond plan §5:
  - If the camera isn't on an unpunched two-shot when an emotion lands (e.g. the reaction right after a punchline punch-in or close-up), the director cuts straight to the face, shot–reverse-shot style.
  - The punchline → reaction close-up pair is exempt from the 3 s close-up budget.
  - The cut back to `two` waits until a close-up has held 1 s, so a short silent beat J-cuts into the next line. This cut-back doesn't count as the next beat's camera event, so a punchline can still punch in on its last word.
  - The punch-in is a 5-frame spring to 1.28× about the subject's head.
  - Shake zooms in by up to 5% so it never shows past the set's edges.
- **The POV card hides during face framings** (medium/close/extreme): a face close-up puts the head exactly where the card sits. This answers the M2 open question. The card returns on the next wide/two shot.
- **A slam text ends at the next cut.**
- **Dropped props stay put in stage space.** `evalActor` takes an optional `rootAt(frame)`. A dropped prop is re-expressed from the owner's root/facing at the drop frame to the current one, so `slideTo` and `turn` no longer drag it along.
- **SFX are synthesized in code** (`pnpm sfx`, `scripts/sfx-gen.ts`): 16 deterministic stings (pop, boing, whoosh, swish, zip, record-scratch, boom, ding, buzzer, crickets, rimshot, slide-up/down, sad-trombone, thud, sparkle). Like the set kit, they are our own work, licensed CC0-1.0 in `src/data/sfx.json`. The generator keeps hand-added licensed entries, so real library files can replace or join them later. Each has a manifest `gain`, because synthesized levels vary.
- **`pnpm render <skitId>`** replaces the old `render` alias. Anything that isn't a skit id passes through to `remotion render`, so the lab commands still work. `render:comp` is the raw alias.
- **Voices for dev:** `character.voice.say` (Milo = Daniel, June = Samantha). The character `voice` block is now all-optional hints for the harness.
- **Director defaults approved by the team** (2026-09-26): `out/fine.mp4` timing and cuts, all 16 synthesized stings in `SfxLab.mp4` (none dropped), the `reactions.json` table, the POV card hiding during face framings, and the default timing (250 ms line gap, 1.3 s reaction close-up) all stay as built.

## 2026-09-26 (M5 self-check + director skill)
- **Built ahead of the M4 market gate.** Plan §0/§8 say M5 onward waits for it. The team still has to post the 3 real skits; the gate is the next decision point, and nothing here changes what it measures.
- **The self-check runs on the compiled timeline, not on pixels** (`src/engine/qa/`). Story checks (`story.ts`): `punchline-camera`, `punchline-reaction`, `emotion-closeups`, `closeup-budget`, `closeup-hold`, `punch-gap`, `one-thing`, `hook`, `length`. Visual checks (`visual.ts`) sample frames (just after every cut, mid-shot, each punch-in peak, each slam, each caption page) and test geometry: `faces-safe`, `overlay-collision`, `overlay-fit`, `contrast`.
- **Levels:** errors block the MP4 in `pnpm direct` and `pnpm batch` (unless `--skip-check`); warnings and infos are reported only. Errors: punchline without a cut or punch-in, no reaction after the punchline, a strong emotion with no face close-up (outside the budget), the face-shot subject leaving the safe area, and text fill vs outline contrast under 4.5:1.
- **Thresholds** reuse the director's constants, so the check and the director can't disagree: close-up budget 3 s, close-ups hold ≥ 1 s, punch-ins ≥ 1.5 s apart, camera events ≥ 8 frames apart, the first line within 1 s (hook), 15–30 s length (info only). A character outline under 3:1 against any set tone is a warning.
- **Exemptions that keep the check honest, not noisy:** the punchline → reaction close-up is one move (not a pile-up, not a second budget hit); close → extreme on the same face is one escalating close-up; skit-directed shots are the author's call; a slam is the beat's one dominant thing; faces crossing the frame edge during entrances/exits are fine; matching contact poses (a high-five) are one shared gesture; in a face shot or punch-in only the subject's face must stay safe.
- **`pnpm direct <id>`** is the M5 loop: validate → voices → prep → compile → self-check → contact sheet → MP4, and it writes `generated/direct.json` (per-step status) for the skill to read. Missing voices tell you to run the harness TTS, or pass `--say` for dev voices. `pnpm check` preps first (cached).
- **The skill never writes jokes** (`skills/skit-director/SKILL.md`, linked into `.claude/skills`). It may not change, add or remove a spoken line; the only text it writes is slam text that repeats a word from a line, a POV card from the human's situation, and the post description/hashtags. At most 3 fix iterations, then it hands back. Its 3 annotated examples are compiled by the tests so they can't rot.

## 2026-09-26 (M6 production loop)
- **Templates stage a `premise.json`** (human lines + `setup` / `escalation` / `punchline` roles) into a draft `skit.json` via `pnpm new <id>`. Five templates: `exchange`, `interview`, `me-vs-me`, `pov-monologue`, `text-slam`. The draft passes the self-check; it's blocking to refine, not the final answer.
- **Template defaults** (`src/engine/templates/stage.ts`): roles set expressions (setup `neutral`, escalation `annoyed`, punchline `deadpan`); each escalation line gets one gesture in turn (`point`, `hands-on-hips`, `shrug`, `arms-crossed`) at 15% of the line; the punchline gets 450 ms of dead air before it and a 300 ms hold after. Without roles, the first line is setup, the last is the punchline, and the rest escalate.
- **Per-template staging:** default sets `exchange` / `me-vs-me` → `living-1`, `interview` → `street-1`, `pov-monologue` / `text-slam` → `plain-1`. The interviewer holds the mic to their own mouth on their lines and out to the guest on the guest's (150 ms early). POV monologue looks at the camera. `me-vs-me` requires a `label` per cast member (cast name labels). Text-slam beats are silent slams of at most 40 characters, sized 1.2–2.2 s by length, with `pop` on each and `boom` on the last.
- **Slam text autofits:** 190 px on one line, shrinking to 130 px before it goes to two lines, and never below 96 px; it's clamped to the safe area. Overlay geometry (subtitles, POV card, slam) is centered on the safe area, not the frame.
- **Director rules found while building templates:** a silent punchline still gets a camera event; the director never cuts to a close-up away from a slam; a punchline emotion close-up falls back to a punch-in when the line is too short to hold 1 s.
- **`pnpm batch <ids…>`** (or `--all`, which skips `*lab` skits) writes `out/posts/<id>/<id>-<title slug>-<hash>.{mp4,srt,txt,json}`. The hash (8 hex) covers the compiled program **plus** everything under `src/engine`, `src/app`, `src/data`, `public/sfx` and `public/fonts`, so an engine change re-renders and an unchanged skit is skipped (`--force` overrides). Hashing the program alone would skip a skit whose pixels changed because the engine did.
- **Post text** (`.txt`): description (else the title), hashtags, the AI-voice note (`meta.syntheticVoices`), then the script as `Name: line`. The `.json` manifest reminds the poster to tick the platform's AI-generated label. The `.srt` is the compiled caption pages, word-for-word from the script.
- **Cast bible:** `src/data/characters/<id>.md` (personality, voice, catchphrases) beside each character JSON; a test fails if a character has no bible. The skill reads it before staging.

## 2026-09-26 (plan §7 items)
- **Walk / run** are swing cycles over the current pose while the root moves linearly (plan: "simple, not IK"). Walk: 18-frame cycle, 0.95 figure heights/s; run: 12 frames, 2.2 figure heights/s, with more lean. They ease in and out over 3 frames. Feet may slide a little, by design. The rig's lowest-foot grounding gives the body bob.
- **Off-stage marks** `off-left` (−0.22) and `off-right` (1.22) exist on every set for entrances and exits. After a walk the character faces the nearest on-stage character.
- **Contact actions measure the rig's real arm reach**, so hands meet whatever the proportions. `highFive`: both step in over 8 frames and hold 14. `shove`: the shover steps in so their hand lands on the target's chest; the target recoils, hops (0.04) and staggers back, clamped to x 0.22–0.78 so the face can still be framed.
- **Multi-scene skits:** `scenes[]` with a per-scene set, cast overrides and POV. The default transition is a 400 ms fade (`cut`, `fade`, `slide`, `wipe`, `clock-wipe`, via `@remotion/transitions`). The punchline is global: flagged beats, else the last spoken beat of the whole skit. Beat ids are unique across scenes (they name voice files). Group shots fit everyone at the cut and wherever they walk before the next cut.
- **Lip-sync to existing audio:** `"audio": { "source": "file", "src", "startMs", "endMs" }` beats are trimmed to a stereo clip in `generated/clips/`, and analysis runs on a mono copy. Word timings come from, in order, manual `audio.words`, the whisper.cpp adapter (`WHISPER_MODEL` + `whisper-cli`), or a silence-based estimate (with a warning). Mouths come from Rhubarb. Clips are hash-cached like TTS lines; beats cut from the same file keep the source timing.
- **Face shots settle and step back** (latest). An emotion close-up waits until a moving subject's move ends. The locked-off face camera frames the head's average position over the shot's first second and where it settles. If the face would leave the safe area, the framing steps back (extreme → close → medium) and the shot reason says so. The compiler takes the safe area as an input for this.
- **Safe area per platform:** `src/data/safe-area-profiles.json` holds TikTok, Reels and Shorts, all `verified: false` (starting guesses); `pnpm safearea` writes the strictest margin per side to `safe-area.json`; `SafeAreaLab` overlays them on a real screenshot. Team screenshots are still needed.

## 2026-09-26 (OSS prep)
- **Every persisted document has `schemaVersion`** and goes through `migrate(kind, doc)` on load. All kinds are at version 1 with no migrations yet. A version newer than the engine, or a gap in the chain, is a `schema-version` diagnostic. Bump `CURRENT_VERSIONS` and add an `n → n+1` migration for any incompatible change.
- **Every diagnostic has a stable machine-readable `code`** (e.g. `duplicate-id`, `unknown-cast-member`, `template-cast`, `slam-length`), shown in formatted output, so the skill and the harness can branch on it without parsing messages.
- **Engine vs node vs app:** the core entry is pure (no React, no Node). File and tool work lives in `src/node` behind adapter interfaces (normalizer, probe, lip-sync, transcriber) with ffmpeg / WAV / Rhubarb / whisper.cpp implementations, plus a Remotion render backend (progress, cancel, timeout, concurrency). Prepared lines record provenance (`source.words`: tts / manual / whisper / estimated; `source.mouth`). `scripts/lib` are thin wrappers.
- **`packages/stickstage`** exports `stickstage` (core), `/schema` (zod + JSON Schemas via `pnpm schema`), `/remotion` (components, `calculateStickStageMetadata`) and `/node`. Remotion packages are peer dependencies pinned to 4.0.529. It's `private: true` and `UNLICENSED` until the team picks a license; the README carries the Remotion license notice.
- **`pnpm lib:pack-test`** is the boundary guard: it installs the packed tarball into a clean fixture, type-checks it, asserts private paths fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`, and compiles, checks and renders a still through a consumer-owned composition.
- **Tooling note:** Remotion's bundled ffmpeg is a minimal build (no `volumedetect`, no raw PCM muxer, no stdout output through `remotion ffmpeg`). To inspect audio, decode to a WAV file.

- **Skit schema v2** (migration 1 → 2 is a no-op: every v1 skit is a valid v2 skit). It adds `narrator`, beat `focus`, scene `card`, `list` text cues, and allows `"cast": []` on a scene. Fixtures, templates and docs now write v2; old skits load through `migrate`.
- **Narrator = voice-over beats** (`speaker` = `narrator.id`). They stay in `skitLines` / `voice.json` with `narrator: true`, so the voice contract and the render service don't change; `POST /validate` gives them `narrator.voice` as the hint. Prep aligns their words but skips lip-sync (`mouthCues: []`, `source.mouth: "none"`, a distinct cache key). Tracks skip them: no mouth, no listener gaze or reaction. `reactorFor` never returns the narrator; for a voice-over beat it returns `focus`. A narrator beat can't carry `expression` (error `narrator-expression`); `focus` on a cast line is an error (`focus-not-narration`).
- **Voice-over camera:** plain voice-over holds the scene's shot (back to two after a close-up has held). An emotion acted under it gets the silent-beat emotion close-up, unless the scene ends before it can hold 1 s (then the QA reports info, not an error). A voice-over punchline: emotion close-up if the budget allows, else a punch-in on `focus` on the last word; with no `focus`, its slam is the camera event (the QA accepts that). The reaction beat comes from `focus`; without one the QA asks for `focus` or `reaction: false`.
- **Captions:** narrator pages carry `narrator` and render italic (default) or boxed in the dialog's place. The `.srt` names the narrator on each voice-over line's first cue, and the post text uses `narrator.name` ("Narrator").
- **QA:** `narrator-dominant` warns above 60% voice-over of the spoken time. When a skit has any voice-over, `length` targets 30–60 s ("explainers") instead of 15–30 s. This is the only length change so far; per-format targets wait for step D.
- **Cards** are a scene field: the set dims under a scrim, a kicker pill shows from the scene start, and the title (190 → 96 px, ≤ 3 lines, `\n` forces breaks) pops in with the slam's drop-in, one anchor per line or one anchor with a 5-frame stagger. A card scene's cast defaults to nobody.
- **Lists** stack **from the top** of the band above the subtitles (not centered). The director cuts to `wide` for a beat with a list so faces sit under it: in 9:16, a centered list or the one-person two-shot put the text on the face (seen in the lab). A list leaves at the first cut after its first item; the QA warns if a cut would hide items still to come, if items don't fit at 60 px, or if the list covers a face.
- **Not built (plan "nice to have"):** `split` contrast (two scenes with a `slide` do it; the Endowment skit uses that), sign `text` on `hold`, chalkboard `text`, laptop screen content, and inner-monolog `voiceOver` on cast beats.
- **`pnpm voice:say <id> --narrator-rate=<wpm>`** speeds up the dev narrator only. At macOS defaults the Endowment script voices to 62 s of speech.
- **The Endowment Effect** (`public/skits/endowment-effect`): the §4 skit, hand-authored with the human lines unchanged (some split into beats). One slam deviates from the §4 table: "They're destroying everything I've built." is 41 characters, over the 40-character slam limit, so the slam reads "EVERYTHING I'VE BUILT." Findings for the team gate: it runs **~71 s**, not ~55 s (55 s of it is speech, with the narrator at 215 wpm), and voice-over is **76%** of the talking, so the plan's own `narrator-dominant` rule fires. Either the script gets trimmed or the threshold is wrong for explainers; that's the team's call at gate C. Step D waits for gate C.

## 2026-09-27 (writer contract)
Plan: `../planning/2026-09-27-writer-contract/plan.md`. Writer version `w1`.
- **The model writes words. StickStage writes everything else.** A reply is title, description, hashtags, and scenes of `{who, text, expression?, slam?, delivery?}`. Optional `pov`, and `set` or `template` only when the brief left them open. StickStage assigns schema version, cast, line roles, the punchline (last line of the last scene), marks, shots, cameras, actions, timing, transitions and SFX.
- **A premise is still schema 1.** One scene stays `lines` (staged as `beats`). Two to four scenes stay `scenes[]` and stage as skit `scenes`. Beat ids run `l1…` across the skit. A scene `cast` replaces the whole cast, so a seated scene names everyone and marks only the ones who sit.
- **Corrections are warnings, not failures.** An unknown mood becomes `neutral`. A fixed set or template ignores the model's value. A wrong scene count is flattened and split evenly when there are enough lines. A short or long line count warns `line-count`. Zero lines, empty text, an unknown speaker, fewer lines than scenes, or non-JSON is unusable: `422 invalid-reply` with one repair prompt.
- **A change request sees lines only** (`id`, `who`, `text`, `expression`). An unchanged line keeps its staging, and silent beats stay with the spoken line they follow. Changed words are restaged. The punchline pause moves to the new last line.
- **`POST /write/prompt`** (`mode: draft | revise`) returns `{system, prompt, writer, catalogVersion}`. `POST /validate` also accepts `{reply, brief}` and `{reply, skit}`. `pnpm write` is the same contract from the repo. `skills/topic-to-video` calls it and no longer carries the joke recipe or the set table.
- **Model profile pin is `MiniMax M3`** (`openrouter`, `minimax/minimax-m3:exacto`). The Tamtree Dev workspace default is OpenRouter gpt-4o-mini, and the old flow noted that gpt-4o-mini under-writes. The stick-script flow pins MiniMax M3 on both chat nodes. Short set tags stay deferred until after the evaluation.
